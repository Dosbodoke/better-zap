Better Zap requires credentials from your Meta WhatsApp Business App and a database implementation for message logging.

## Config Object

The `betterZap()` function accepts a configuration object:

```ts
import { betterZap } from "@better-zap/hono";

const zap = betterZap({
  database: { whatsappLog: myDatabase },
  config: {
    token: "your_access_token",
    phoneId: "your_phone_number_id",
    webhookToken: "your_verify_token",
    appSecret: "your_app_secret",
  },
  webhook: {
    onMessage: async (ctx) => { /* ... */ },
    onStatusUpdate: async (ctx) => { /* ... */ },
  },
  // Optional
  basePath: "/api/whatsapp",     // Default: "/api/whatsapp"
  templates: myTemplates,         // From defineTemplates()
  plugins: [myPlugin],            // Plugin array
  conversationSync: env.SYNC_DO,  // Durable Object namespace
  media: { maxBytes: 25 * 1024 * 1024 }, // Media download settings
  logger: { level: "info" },      // Logger config
});
```

## Config Properties

### `config` (required)

WhatsApp Cloud API credentials:

| Property | Type | Description |
| --- | --- | --- |
| `token` | `string` | System User access token from Meta Business Manager |
| `phoneId` | `string` | Phone Number ID registered in your WhatsApp Business App |
| `webhookToken` | `string` | A secret string you choose — Meta sends it during webhook verification |
| `appSecret` | `string` | App Secret from your Meta App Dashboard — used for HMAC-SHA256 signature verification |
| `environment` | `string?` | Set to `"development"` to skip real API calls and return mock responses. Media downloads still run, since they send nothing |
| `defaultCountry` | `"BR" \| false` | How numbers without a country code are read. Defaults to `"BR"`: a 10 or 11 digit number gets `55` in front. Set to `false` when you message numbers outside Brazil, and pass every number in international format |
| `defaultTemplateLanguage` | `string?` | Language code used by template sends that pass none. Defaults to `"pt_BR"` |

Better Zap stores one canonical phone per contact. Brazilian mobile numbers always use the 13-digit form with the ninth digit, in both directions. Apps outside Brazil should set `defaultCountry: false`, because with the default an 11-digit international number such as a US number without `+` is read as a Brazilian national number.

### `database` (required)

An object containing your database implementation:

```ts
interface BetterZapDatabase {
  whatsappLog: WhatsAppLogStore;
  coexistence?: CoexistenceStore;
  media?: MediaStore;
}
```

The `WhatsAppLogStore` interface defines the methods Better Zap needs for message logging. You must implement this interface with your database of choice (D1, Prisma, Drizzle, etc.).

`coexistence` stores [coexistence](/docs/guides/self-hosted-coexistence) accounts, contacts and sync jobs.

`media` stores incoming media files. Without it, Better Zap keeps only the text label (`[imagem: foto]`) and Meta's media id, and Meta deletes the file after 7 days. Use `createS3MediaStore` from `better-zap/s3` for R2, AWS S3, MinIO or B2, or implement the interface yourself:

```ts
interface MediaStore {
  put(
    key: string,
    body: ReadableStream<Uint8Array> | ArrayBuffer,
    info: { contentType: string; size?: number; sha256?: string },
  ): Promise<void>;
  get(key: string): Promise<{
    body: ReadableStream<Uint8Array>;
    contentType: string;
    size?: number;
  } | null>;
  delete?(key: string): Promise<void>;
  /** When present, the media route redirects images, audio, video and PDFs here instead of streaming. Must stay valid for `expiresInSeconds` (at most 7 days). */
  getSignedUrl?(key: string, expiresInSeconds: number): Promise<string>;
}
```

See [Media Storage](/docs/guides/media-storage) for setup.

See the [WhatsAppLogStore interface](#whatsapplogstore-interface) section below for the full interface.

### `webhook` (required)

Callback functions for incoming WhatsApp events:

```ts
webhook: {
  onMessage: async (ctx) => {
    // ctx.message   — raw WhatsApp message object
    // ctx.content   — extracted human-readable content
    // ctx.phone     — sender phone number (normalized)
    // ctx.contact   — sender contact info
    // ctx.db        — your database
    // ctx.api       — WhatsAppService instance
    // ctx.logger    — MessageLoggerService instance
  },
  onStatusUpdate: async (ctx) => {
    // ctx.status    — { id, status, timestamp, recipientId }
    // ctx.db        — your database
    // ctx.api       — WhatsAppService instance
    // ctx.logger    — MessageLoggerService instance
  },
}
```

### `basePath` (optional)

The URL prefix for all routes. Defaults to `"/api/whatsapp"`.

All API routes are mounted under this path:
- `GET  {basePath}/webhook` — Meta webhook verification
- `POST {basePath}/webhook` — Incoming messages/statuses
- `POST {basePath}/send/text` — Send text messages
- `POST {basePath}/send/template` — Send templates
- `POST {basePath}/send/interactive` — Send interactive messages
- `POST {basePath}/send/location` — Send location
- `GET  {basePath}/conversations` — List conversations
- `GET  {basePath}/conversations/:phone` — Get conversation
- `GET  {basePath}/conversations/:phone/messages` — Paginated messages
- `GET  {basePath}/media/:waMessageId` — Stored media file
- `POST {basePath}/coexistence/embedded-signup/callback` — Completes Embedded Signup
- `GET  {basePath}/coexistence/phone-numbers/:phoneNumberId/status` — Phone number coexistence status
- `POST {basePath}/coexistence/phone-numbers/:phoneNumberId/sync/contacts` — Request contact sync
- `POST {basePath}/coexistence/phone-numbers/:phoneNumberId/sync/history` — Request history sync

The coexistence routes are described in [Self-hosted Coexistence](/docs/guides/self-hosted-coexistence).

### `authorizeAppRequest` (optional)

Guards the app routes: every route under `basePath` except the two webhook routes. Until you set it, app routes answer `401`, so nobody can send messages or read conversations through your API by default. Pass a function that returns `true` for requests you allow, or `"public"` if something in front of Better Zap already authenticates them. A webhook-only bot can leave it out.

```ts
authorizeAppRequest: ({ request }) => {
  const authorization = request.headers.get("Authorization");
  return authorization === `Bearer ${env.APP_API_TOKEN}`;
},
```

See [Authorization](/docs/reference/server#authorization) for every response and log.

### `templates` (optional)

A template registry created with `defineTemplates()`. Enables type-safe template sending.

```ts
import { defineTemplates } from "better-zap";

const templates = defineTemplates({
  order_confirmation: {
    language: "en",
    components: [
      {
        type: "body",
        parameters: [
          { type: "text", name: "customerName" },
          { type: "text", name: "orderId" },
        ],
      },
    ],
  },
});
```

See [Template Registry](/docs/concepts/template-registry) for details.

### `plugins` (optional)

An array of Better Zap plugins. Plugins can inject context, services, and hooks.

```ts
plugins: [myQueuePlugin, myAnalyticsPlugin]
```

See [Plugins](/docs/concepts/plugins) for details.

### `conversationSync` (optional)

A Cloudflare Durable Object namespace for real-time conversation sync across workers.

```ts
conversationSync: env.CONVERSATION_SYNC
```

See [Durable Objects](/docs/concepts/durable-objects) for details.

### `media` (optional)

Media download settings. Downloads only run when `database.media` is set.

| Property | Type | Description |
| --- | --- | --- |
| `maxBytes` | `number?` | Files larger than this are skipped. Defaults to 25 MiB |
| `timeoutMs` | `number?` | Time limit in milliseconds for one file's download and upload. Slower files are recorded as `failed`. Defaults to `30000` |
| `concurrency` | `number?` | Files downloaded at the same time, in the background after `onMessage`. Defaults to `3` |
| `signedUrlExpiresIn` | `number?` | Lifetime in seconds of the presigned URL the media route redirects to, when the store has `getSignedUrl`. Capped at 7 days. Defaults to `3600` |

See [Media Storage](/docs/guides/media-storage) for details.

## WhatsAppLogStore Interface

You must implement this interface to provide message persistence:

```ts
type CreateWhatsAppLogParams = {
  phone: string;
  userId?: string;
  contactName?: string;
  direction: WhatsAppDirection;
  messageType: WhatsAppMessageType;
  content: string;
  templateName?: string;
  waMessageId?: string;
  status: WhatsAppStatus;
  errorMessage?: string;
  metadata?: any;
  sentAt: string;
};

interface WhatsAppLogStore {
  createWhatsAppLog(
    params: CreateWhatsAppLogParams,
  ): Promise<{ record: WhatsAppLogRecord; created: boolean }>;

  getMessageByWaId(waMessageId: string): Promise<WhatsAppLogRecord | null>;
  updateWhatsAppLogByWaMessageId(
    waMessageId: string,
    updates: Partial<WhatsAppLogRecord>,
  ): Promise<void>;
  updateStatusIfProgressed(
    waMessageId: string,
    newStatus: WhatsAppStatus,
    updates: Partial<WhatsAppLogRecord>,
  ): Promise<boolean>;
  getConversationById(conversationId: string): Promise<ConversationRecord | null>;
  getConversationByPhone(phone: string): Promise<ConversationRecord | null>;
  getConversations(): Promise<ConversationRecord[]>;
  getMessagesByConversationPaginated(
    conversationId: string,
    cursor?: string | null,
    limit?: number,
  ): Promise<
    Array<{
      id: string;
      phone?: string;
      content: string | null;
      direction: string;
      status: string;
      sentAt: string;
      templateName?: string | null;
      messageType?: string | null;
      metadata?: any;
    }>
  >;
  hasRecentOutgoingMessage(phone: string, withinHours: number): Promise<boolean>;
}
```

`createWhatsAppLog` must be atomic when `params.waMessageId` is present.
Incoming webhook deduplication depends on this method inserting the row or
returning the existing row and `created: false` in one database operation or
transaction. When `waMessageId` is omitted, return the inserted row with
`created: true`.

The SDK also uses that existing row for coexistence history media. History sync
sends older media as a `media_placeholder` message with no content. For media
sent within 14 days of onboarding, Meta later sends the same message id with
the real media. When the existing row still holds a placeholder
(`hasPendingMedia(record)`), Better Zap replaces its `content` and `metadata`
through `updateWhatsAppLogByWaMessageId`. A placeholder never overwrites real
content. Your store needs no extra method for this.

When `database.media` is set, Better Zap also reads the row with
`getMessageByWaId` after downloading a message's media, and writes the
reference back as `metadata.media` with `updateWhatsAppLogByWaMessageId`. The
update carries the whole `metadata` object with the existing fields kept, so
your store can overwrite the column. The media route reads the row with
`getMessageByWaId`.

`updateStatusIfProgressed` must be atomic in your database implementation so duplicate or out-of-order webhook status events cannot regress a message.

## Getting Your Credentials

### Access Token

1. Go to [Meta Business Manager](https://business.facebook.com/)
2. Navigate to **Business Settings > System Users**
3. Create a System User with the `whatsapp_business_messaging` permission
4. Generate a token — this is your `token`

### Phone Number ID

1. In your [Meta App Dashboard](https://developers.facebook.com/apps/), go to **WhatsApp > API Setup**
2. Your **Phone Number ID** is displayed under the test number section

### App Secret

1. In your Meta App Dashboard, go to **Settings > Basic**
2. Your **App Secret** is shown (click "Show" to reveal)

### Webhook Verify Token

This is any secret string you choose. You'll use the same value when configuring the webhook URL in Meta's dashboard.
