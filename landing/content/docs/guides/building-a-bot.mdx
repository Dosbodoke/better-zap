Bot replies are a first-class Better Zap workflow. Handle incoming messages in `webhook.onMessage`, then use `ctx.api` to send text, templates, buttons, locations, reactions, and chat actions from the same context.

## Basic Auto-Reply Bot

```ts title="src/index.ts"
import { betterZap } from "@better-zap/hono";

type Reply = {
  keywords: string[];
  response: string;
};

const replies: Reply[] = [
  {
    keywords: ["hello", "hi", "hey", "oi", "ola"],
    response: "Hello! How can I help you today?",
  },
  {
    keywords: ["hours", "horario", "schedule"],
    response: "We're open Monday to Friday, 9am to 6pm.",
  },
  {
    keywords: ["price", "pricing", "preco", "valor"],
    response: "Check out our pricing at example.com/pricing",
  },
];

const zap = betterZap({
  // ...config
  webhook: {
    onMessage: async (ctx) => {
      const content = ctx.content.toLowerCase().trim();

      await ctx.api.markAsRead(ctx.message.id);

      for (const reply of replies) {
        if (reply.keywords.some((kw) => content.includes(kw))) {
          await ctx.api.sendText(ctx.phone, reply.response);
          return;
        }
      }

      await ctx.api.sendText(
        ctx.phone,
        "Thanks for your message! An agent will respond shortly.",
      );
    },
    onStatusUpdate: async () => {},
  },
});

export default zap.handler;
```

Messages sent through `ctx.api.sendText()` are logged as `bot_reply` by default. Pass a custom logging category only when you need to separate a specific flow:

```ts
await ctx.api.sendText(ctx.phone, "Your order is confirmed.", {
  messageType: "order_update",
});
```

## Adding Interactive Menus

Use the same `onMessage` handler for buttons and menus:

```ts
webhook: {
  onMessage: async (ctx) => {
    const content = ctx.content.toLowerCase().trim();

    if (content === "menu" || content === "help") {
      await ctx.api.sendInteractiveButtons(
        ctx.phone,
        "What do you need help with?",
        [
          { id: "help_support", title: "Support" },
          { id: "help_billing", title: "Billing" },
          { id: "help_sales", title: "Sales" },
        ],
      );
      return;
    }

    if (ctx.message.type === "interactive") {
      const buttonId = ctx.message.interactive?.button_reply?.id;

      switch (buttonId) {
        case "help_support":
          await ctx.api.sendText(ctx.phone, "Connecting you to support...");
          return;
        case "help_billing":
          await ctx.api.sendText(ctx.phone, "Let me check your account...");
          return;
        case "help_sales":
          await ctx.api.sendText(ctx.phone, "Our sales team will reach out!");
          return;
      }
    }

    await ctx.api.sendText(
      ctx.phone,
      "Send \"menu\" to choose a support option.",
    );
  },
  onStatusUpdate: async () => {},
}
```

## Showing Typing State

For slower bot flows, show a typing indicator before doing the expensive work:

```ts
webhook: {
  onMessage: async (ctx) => {
    await ctx.api.typingIndicator(ctx.message.id);

    const reply = await generateBotReply(ctx.content);
    await ctx.api.sendText(ctx.phone, reply);
  },
  onStatusUpdate: async () => {},
}
```

## When to Use Plugins

Use plugins for reusable cross-cutting behavior, such as analytics, queue state, shared services, or context injection. Keep the bot's conversation logic in `webhook.onMessage` unless you are intentionally packaging that behavior for reuse across multiple Better Zap apps.
