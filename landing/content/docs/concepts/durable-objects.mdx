Better Zap optionally integrates with Cloudflare Durable Objects to broadcast real-time conversation updates across workers.

## Overview

When `conversationSync` is configured, Better Zap's message logger sends a sync event to a Durable Object whenever:

- A message is stored: incoming, outgoing, or imported from history
- A message's delivery status advances (sent → delivered → read)
- A stored message changes

This enables real-time UI updates across multiple connected clients without polling.

## What Better Zap Does

Every sync event goes to one Durable Object instance, `conversationSync.idFromName("global-workspace")`, as a `POST` to `http://do/sync` whose body is the event as JSON. Delivery failures are logged and never fail the webhook.

## What Your App Provides

Better Zap does not ship the Durable Object class. Your app writes it. This minimal example forwards each event to connected WebSocket clients:

```ts title="src/conversation-sync.ts"
import { DurableObject } from "cloudflare:workers";
import type { SyncEvent } from "better-zap";

export class ConversationSync extends DurableObject {
  async fetch(request: Request): Promise<Response> {
    // Browsers connect here to receive events.
    if (request.headers.get("Upgrade") === "websocket") {
      const pair = new WebSocketPair();
      this.ctx.acceptWebSocket(pair[1]);
      return new Response(null, { status: 101, webSocket: pair[0] });
    }

    // Better Zap posts every sync event here.
    if (request.method === "POST" && new URL(request.url).pathname === "/sync") {
      const event = (await request.json()) as SyncEvent;
      const data = JSON.stringify(event);
      for (const socket of this.ctx.getWebSockets()) {
        socket.send(data);
      }
      return new Response("OK");
    }

    return new Response("Not found", { status: 404 });
  }
}
```

## Setup

Pass your Durable Object namespace binding to `betterZap()`:

```ts title="src/index.ts"
const zap = betterZap({
  // ...config
  conversationSync: env.CONVERSATION_SYNC,
});
```

Configure the binding in `wrangler.toml`:

```toml title="wrangler.toml"
[durable_objects]
bindings = [
  { name = "CONVERSATION_SYNC", class_name = "ConversationSync" }
]

[[migrations]]
tag = "v1"
new_classes = ["ConversationSync"]
```

Export the class from your Worker's entry file. After your app has authenticated a browser's WebSocket request, route it to the same instance:

```ts
const id = env.CONVERSATION_SYNC.idFromName("global-workspace");
return env.CONVERSATION_SYNC.get(id).fetch(request);
```

## Sync Events

Three types of events are sent. `message` is a `WhatsAppLogRecord` and `conversation` is a [`Conversation`](/docs/reference/conversations#response).

### `NEW_MESSAGE`

Sent when a message is stored: incoming, outgoing, or imported from history.

```ts
{
  type: "NEW_MESSAGE",
  message: WhatsAppLogRecord,
  conversation: Conversation,
}
```

### `STATUS_UPDATE`

Sent when a message's delivery status advances.

```ts
{
  type: "STATUS_UPDATE",
  waMessageId: string,
  status: "sent" | "delivered" | "read" | "failed",
  timestamp: string, // ISO-8601
  deliveredAt?: string | null,
  readAt?: string | null,
}
```

### `MESSAGE_UPDATE`

Fired when a stored message changes. This happens when a coexistence history
media placeholder is replaced by the real media, and when a message's media
file is stored (or fails to download) and `metadata.media` is set. See
[Media Storage](/docs/guides/media-storage).

```ts
{
  type: "MESSAGE_UPDATE",
  message: WhatsAppLogRecord, // with the new content and metadata
}
```

The `SyncEvent` type also contains `CONVERSATION_UPDATE`. It is reserved and not sent today.

## Without Durable Objects

If you don't pass `conversationSync`, Better Zap works normally without real-time sync. The sync notifier is a no-op when unconfigured.
