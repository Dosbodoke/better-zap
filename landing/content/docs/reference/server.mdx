The `betterZap()` function from `@better-zap/hono` is the main entry point. It creates a Hono application with webhook handling, API routes, and returns a programmatic API for server-side use.

## Usage

```ts
import { betterZap } from "@better-zap/hono";

const zap = betterZap({
  database: { whatsappLog: myDatabase },
  config: {
    token: env.WHATSAPP_TOKEN,
    phoneId: env.WHATSAPP_PHONE_ID,
    webhookToken: env.WEBHOOK_VERIFY_TOKEN,
    appSecret: env.WHATSAPP_APP_SECRET,
  },
  webhook: {
    onMessage: async (ctx) => { /* ... */ },
    onStatusUpdate: async (ctx) => { /* ... */ },
  },
  authorizeAppRequest: ({ request }) => {
    return request.headers.get("Authorization") === `Bearer ${env.APP_API_TOKEN}`;
  },
});
```

## Authorization

Meta webhook routes must stay public so Meta can verify and deliver events. Every other route is an app route, and app routes answer `401` until you set `authorizeAppRequest`. A webhook-only bot needs nothing here: its webhook routes keep working without the option.

```ts
authorizeAppRequest?: BetterZapAuthorizeAppRequest | "public";

type BetterZapAuthorizeAppRequest = (input: {
  request: Request;
  env?: unknown;
}) => boolean | Promise<boolean>;
```

An app route behaves like this for each value:

| `authorizeAppRequest` | Response | Log |
| --- | --- | --- |
| function returning `true` | the route handler runs | none |
| function returning `false` | `401` `{ "error": "Unauthorized" }` | none |
| function that throws | `500` `{ "error": "Authorization failed" }` | `app_api.authorization_failed` (error) |
| `"public"` | the route handler runs | none |
| omitted | `401` `{ "error": "Unauthorized", "code": "app_authorization_not_configured" }` | `app_api.authorization_not_configured` (warn) |

Use `"public"` only when something in front of Better Zap already authenticates the request, such as a gateway, a private network or your own middleware.

The option guards:

- `POST /send/text`
- `POST /send/template`
- `POST /send/interactive`
- `POST /send/location`
- `GET /conversations`
- `GET /conversations/:phone`
- `GET /conversations/:phone/messages`
- `GET /media/:waMessageId`
- `POST /coexistence/embedded-signup/callback`
- `GET /coexistence/phone-numbers/:phoneNumberId/status`
- `POST /coexistence/phone-numbers/:phoneNumberId/sync/contacts`
- `POST /coexistence/phone-numbers/:phoneNumberId/sync/history`

It never applies to `GET /webhook` or `POST /webhook`.

## Return Value

`betterZap()` returns an object with three properties:

### `handler`

A standard `fetch` handler compatible with Cloudflare Workers:

```ts
handler: (request: Request, env?: any, executionCtx?: any) => Promise<Response>
```

Use it as your worker's default export:

```ts
export default { fetch: zap.handler };
```

### `api`

A programmatic API for sending messages, querying conversations and managing message templates from your server code. No HTTP calls — it uses the services directly.

```ts
// Send a text message
await zap.api.send.text("+5511999998888", "Hello!");

// Send a template
await zap.api.send.template("+5511999998888", "order_confirmed", {
  params: { customerName: "John", orderId: "12345" },
});

// List conversations
const conversations = await zap.api.conversations.list();

// Get messages for a conversation
const messages = await zap.api.conversations.messages("+5511999998888", {
  limit: 50,
});

// Manage templates in Meta (needs config.wabaId)
const approved = await zap.api.templates.list({ status: "APPROVED" });
```

See [Messages](/docs/messages/send-text), [Conversations API](/docs/reference/conversations) and [Template Management](/docs/reference/templates#with-betterzap) for the full reference.

### `services`

Core services plus any services injected by plugins:

```ts
// Always available
zap.services.whatsapp   // WhatsAppService instance
zap.services.logger     // MessageLoggerService instance

// Plugin services (type-safe when plugins are configured)
zap.services.myQueue    // From a queue plugin, for example
```

## HTTP Routes

The handler automatically registers these routes under `basePath` (default: `/api/whatsapp`):

| Method | Path | Description |
| --- | --- | --- |
| `GET` | `/webhook` | Meta webhook verification (challenge response) |
| `POST` | `/webhook` | Incoming messages and status updates |
| `POST` | `/send/text` | Send a text message |
| `POST` | `/send/template` | Send a template message |
| `POST` | `/send/interactive` | Send interactive messages (buttons, lists, carousel) |
| `POST` | `/send/location` | Send a location message |
| `GET` | `/conversations` | List all conversations |
| `GET` | `/conversations/:phone` | Get a single conversation |
| `GET` | `/conversations/:phone/messages` | Get paginated messages |
| `GET` | `/media/:waMessageId` | Stored media file of a message. See [Media Storage](/docs/guides/media-storage) |
| `POST` | `/coexistence/embedded-signup/callback` | Completes Embedded Signup. See [Self-hosted Coexistence](/docs/guides/self-hosted-coexistence) |
| `GET` | `/coexistence/phone-numbers/:phoneNumberId/status` | Phone number coexistence status. See [Self-hosted Coexistence](/docs/guides/self-hosted-coexistence) |
| `POST` | `/coexistence/phone-numbers/:phoneNumberId/sync/contacts` | Request contact sync. See [Self-hosted Coexistence](/docs/guides/self-hosted-coexistence) |
| `POST` | `/coexistence/phone-numbers/:phoneNumberId/sync/history` | Request history sync. See [Self-hosted Coexistence](/docs/guides/self-hosted-coexistence) |

## Webhook Processing

The webhook handler is designed for speed:

1. **Verification** (`GET /webhook`) — Responds to Meta's challenge with the verify token
2. **Message processing** (`POST /webhook`) — Validates the HMAC-SHA256 signature, checks for duplicate messages, then:
   - Returns `200 OK` to Meta immediately (within ~20ms)
   - Processes the message asynchronously via `executionCtx.waitUntil()`
   - Logs incoming messages automatically
   - Downloads incoming media into `database.media`, when configured
   - Runs plugin hooks, then your `onMessage`/`onStatusUpdate` callbacks
