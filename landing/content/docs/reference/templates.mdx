`TemplateService` from `better-zap` creates, reads, edits and deletes message templates through Meta's template management API. It is a server-side class. It adds no HTTP routes: your app calls it from its own server code, for example from a dashboard's backend, and decides who may use it.

## Setup

The access token needs the `whatsapp_business_management` permission. The WhatsApp Business Account ID is shown in WhatsApp Manager under account settings, and in the App Dashboard on the WhatsApp **API Setup** page.

```ts
import { TemplateService } from "better-zap";

const templates = new TemplateService({
  accessToken: env.WHATSAPP_TOKEN,
  wabaId: env.WHATSAPP_BUSINESS_ACCOUNT_ID,
});
```

Every method also accepts `wabaId` and `accessToken`. A value passed to a call wins over the constructor's for that call.

Templates keep Meta's own shape: snake_case keys and upper-case values such as `"UTILITY"` and `"BODY"`. A template read with `get` can be changed and passed back to `update` as it is.

## With betterZap()

An app that uses `betterZap()` from `@better-zap/hono` does not need its own `TemplateService`. Set `config.wabaId` and call the same methods on `zap.api.templates`. It uses `config.token`.

```ts
import { betterZap } from "@better-zap/hono";

const zap = betterZap({
  database,
  config: {
    token: env.WHATSAPP_TOKEN,
    phoneId: env.WHATSAPP_PHONE_ID,
    webhookToken: env.WHATSAPP_VERIFY_TOKEN,
    appSecret: env.WHATSAPP_APP_SECRET,
    wabaId: env.WHATSAPP_BUSINESS_ACCOUNT_ID,
  },
  webhook: { /* ... */ },
});

const result = await zap.api.templates.create({
  template: {
    name: "order_confirmation",
    language: "en_US",
    category: "UTILITY",
    components: [{ type: "BODY", text: "Your order is confirmed." }],
  },
});
```

Each method returns the same result as the `TemplateService` method of the same name. Without `config.wabaId`, a call that passes no `wabaId` returns a `configuration_error` failure; `betterZap()` itself starts without it. `environment: "development"` does not mock these calls: they always reach Meta.

`api.templates` is server-side only. `betterZap()` adds no HTTP route and `createZapClient` has no method for it, because template management can delete a business's templates and app routes cannot yet be authorized per operation.

`api.templates` manages templates in Meta. It is not the `templates` option of `betterZap()`, which is the typed registry that [`send.template`](/docs/messages/send-template) uses to send them.

To manage [several business accounts](#several-business-accounts), pass your own service as the `templateService` option, for example a `TemplateService` with a `tokenProvider`.

## Methods

### `list`

Returns one page. Filters are optional.

```ts
const result = await templates.list({ status: "APPROVED", language: "pt_BR", limit: 50 });

if (result.success) {
  result.data.templates; // MessageTemplate[]
  result.data.paging; // { before?, after?, hasNextPage }
}
```

Pass `after: result.data.paging.after` to read the next page.

### `listAll`

Follows the page cursors and returns every template. It reads 100 templates per page and stops after `maxPages` pages (default 100), with `truncated: true` when more remain.

```ts
const result = await templates.listAll({ category: "MARKETING" });

if (result.success) {
  result.data.templates;
  result.data.truncated;
}
```

### `get`

```ts
const result = await templates.get({ templateId: "1234567890" });
```

### `create`

```ts
const result = await templates.create({
  template: {
    name: "order_confirmation",
    language: "en_US",
    category: "UTILITY",
    components: [
      {
        type: "BODY",
        text: "Your order {{1}} is confirmed.",
        example: { body_text: [["A-1042"]] },
      },
      { type: "FOOTER", text: "Thanks for shopping with us" },
    ],
  },
});

if (result.success) {
  result.data; // { id, status, category }
}
```

Meta reviews a new template before it can be sent. `status` is usually `"PENDING"` at first.

### `update`

`components` replaces every component of the template.

```ts
const result = await templates.update({
  templateId: "1234567890",
  changes: {
    components: [
      {
        type: "BODY",
        text: "Order {{1}} is confirmed and on its way.",
        example: { body_text: [["A-1042"]] },
      },
    ],
  },
});
```

### `delete`

Deletes one language of a template. It needs both the id and the name.

```ts
await templates.delete({ templateId: "1234567890", name: "order_confirmation" });
```

### `deleteAllLanguages`

Deletes the template in every language.

```ts
await templates.deleteAllLanguages({ name: "order_confirmation" });
```

## Validation

`create` and `update` check a template against Meta's documented limits before they send it. Meta answers a malformed template with error `100` and little detail, and each attempt counts toward the 100 creations per hour, so the check returns every problem at once without calling Meta.

```ts
const result = await templates.create({ template });

if (!result.success && result.issues) {
  result.issues;
  // [{
  //   code: "body_text_too_long",
  //   path: "components[1].text",
  //   message: "Body text is 1031 characters; the limit is 1024.",
  // }]
}
```

`error` is then `"Invalid template: "` followed by the first issue's message, and `diagnostics.kind` is `"invalid_input"`. `update` checks only `changes.components`, and only when it is given. Pass `validate: false` to either method to skip the check and let Meta decide.

### In a form

`validateMessageTemplate` is the same check as a plain function. It has no server dependencies, so a template editor in the browser can run it on every change. It returns `[]` when nothing is wrong. `code` is stable for your own logic, `path` points at the field, and `message` is one English sentence you can show.

```ts
import { extractTemplateVariables, validateMessageTemplate } from "better-zap";

const issues = validateMessageTemplate(draft);
// Show each message next to the field its path names, such as "components[1].text".

// One example input per body variable: "Hi {{1}}, order {{2}}" → ["1", "2"]
const variables = extractTemplateVariables(bodyText);
```

`validateMessageTemplateComponents(components, { category, parameterFormat })` checks only the components, for an edit where the name and language are fixed. Without `parameterFormat` it assumes `NAMED` when any header or body variable is not a number.

### Limits

The limits are exported as `MESSAGE_TEMPLATE_LIMITS`. Lengths are counted in characters.

| Field | Limit |
| --- | --- |
| Name | 512 characters: lower-case letters, digits and underscores |
| Body text | 1024 characters |
| Text header | 60 characters and 1 variable |
| Footer | 60 characters |
| Button text | 25 characters |
| URL button | 2000 characters and 1 variable |
| Phone number button | 20 characters |
| Buttons | 10 in total, 2 URL, 1 phone number, 1 copy code; quick replies next to each other |

The check also requires a body, at most one header, body, footer and buttons component, an uploaded handle for an image, video, document or GIF header, positional variables numbered from `{{1}}` without gaps, named variables in lower case, and an example for every header, body and URL variable.

It does not check authentication templates beyond the name, language and category, or components other than the header, body, footer and buttons: carousels, limited-time offers, flows and other types pass through unchecked. When no category is given, as in most edits, components with a one-time password (`OTP`) button are treated as an authentication template. It does not check content against Meta's policies.

## Results

No method throws. Each returns a result:

```ts
type TemplateResult<TData> =
  | { success: true; data: TData }
  | {
      success: false;
      error: string;
      errorCode?: number;
      errorSubcode?: number;
      errorUserTitle?: string;
      errorUserMessage?: string;
      httpStatus?: number;
      details?: unknown;
      diagnostics: { kind: TemplateFailureKind; retryable: boolean /* ... */ };
      /** Present when the template failed local validation. */
      issues?: MessageTemplateIssue[];
    };
```

`errorUserTitle` and `errorUserMessage` are Meta's explanation for a person, such as "Content in This Language Already Exists". Show those in your UI. `error` is Meta's technical message.

`diagnostics.kind` tells failures apart:

| `kind` | Meaning |
| --- | --- |
| `invalid_input` | The input was rejected before any request: an id that is not numeric, a missing name, empty changes, or a template that failed [validation](#validation) (with `issues`) |
| `configuration_error` | No `wabaId` or no access token |
| `credential_provider_error` | `tokenProvider` threw |
| `graph_error` | Meta returned an error |
| `http_error` | A non-2xx response without a Graph error body |
| `network_error` | The request did not complete |
| `malformed_response` | Meta answered with an unexpected body |

The service never retries. `create` in particular is not safe to repeat blindly.

## Several business accounts

A multi-tenant app can work in either of two ways:

- One `TemplateService` per business account, each with its own `accessToken` and `wabaId`.
- One service with a `tokenProvider`, passing `wabaId` on each call. The provider receives that `wabaId` and returns the token for it.

```ts
const templates = new TemplateService({
  tokenProvider: {
    getAccessToken: ({ wabaId }) => tokens.forBusinessAccount(wabaId),
  },
});

await templates.list({ wabaId: tenant.wabaId });
```

> **`get` and `update` address a template by its id only.** When one token can reach several business accounts, check that the template belongs to the current tenant before you edit it, for example by finding it in `list` for that tenant's `wabaId`.

## Meta's limits

- An edit replaces all components.
- Only `APPROVED`, `REJECTED` and `PAUSED` templates can be edited.
- An approved template can be edited once per 24 hours and 10 times per 30 days, and its category cannot be changed.
- Deleting an approved template blocks its name for 30 days. A `DISABLED` template cannot be deleted.
- A business account can create 100 templates per hour.

## Status changes

Approval, rejection, pausing, quality changes and category changes are not returned by these methods. Meta sends them as webhooks, and Better Zap passes them to the `onTemplateStatusUpdate`, `onTemplateQualityUpdate`, `onTemplateCategoryUpdate` and `onTemplateComponentsUpdate` hooks. See [Template events](/docs/reference/webhook-events#template-events).
